# PR 문서: `feature/pipeline-sse-progress` → `develop`

## 1. 변경 목적

실패한 파이프라인 단계 카드의 `단계 화면 열기` 링크가 현재 상세 화면으로 되돌아가 아무 반응이
없는 것처럼 보이던 문제를 수정한다. 데이터 가공 화면에 backend가 발행하는 실행 후반 체크리스트
단계도 표시한다.

## 2. `develop` 대비 주요 변경

### 실패 단계 화면 이동 수정

- `stageScreenPath()`에서 `FAILED` 상태도 현재 stage의 진행 화면 경로를 계산한다.
- 실패한 데이터 가공 단계의 카드 링크는 `/processing` 화면으로 이동한다.
- 진행 화면에서는 실패 시점의 체크리스트와 실시간 에이전트 로그를 확인할 수 있다.
- `CANCELLED` 상태는 실행 단계가 확정되지 않을 수 있어 기존처럼 상세 화면으로 이동한다.

### 데이터 가공 체크리스트 라벨 확장

기존 계획 수립 4단계에 아래 라벨을 추가한다.

- 원천 데이터 조회
- 데이터 가공·품질 검증
- 최종 산출물 검증
- 결과 파일 생성

## 3. 영향 범위

- `src/shared/pipelineLabels.ts`

API 스키마, 라우트 선언, DB migration 변경은 없다. 추가 체크리스트 상태 이벤트는 별도
`Backend-fastapi` PR이 제공한다.

## 4. 검증 체크리스트

- [x] `npm run build`
- [x] TypeScript 타입 검사 및 Vite production build 통과
- [ ] 실패한 데이터 가공 카드의 `단계 화면 열기`를 눌러 `/processing`으로 이동하는지 확인
- [ ] 데이터 가공 실행 중 8개 체크리스트가 순서대로 표시되는지 확인

## 5. 리뷰 포인트

- `FAILED` 상태에서 `stageScreenPath()`가 상세 화면이 아닌 해당 stage의 진행 화면을 반환하는지
  확인한다.
- backend 이벤트가 아직 없는 기존 실행 건에서도 새 체크리스트 항목은 `PENDING`으로 안전하게
  표시되는지 확인한다.

## 6. 배포 시 유의사항

frontend만 먼저 배포해도 기존 API와 호환된다. 확장된 체크리스트의 실시간 상태는 backend PR이
함께 배포되어야 표시된다.
